# Difference Logic と順序位相ヒント — 否定的結果の記録（2026-09-19）

`feature/difference-logic` と `feature/precedence-phase` の結論。**どちらも採用しない。**
以下は「なぜ入れないか」を後から再検証できるようにするための記録で、
同じ発想が再提案されたときはここを先に読むこと。

## 0. 3行で

- 差分制約（`x - y <= c`）は 273 モデル中 197 に出現するが、**専用伝播が新しく刈れる
  ものは無い**（Phase 1 の伝播が既に不動点に達している）
- DL が SMT で効く2つの柱のうち、theory propagation は既存伝播に包含され、
  theory explanation は ground 限定 NoGood では**表現する場所が無い**
- 派生として試した「順序グラフ上の位置を分岐方向に使う」も、**逆向きの対照と
  区別がつかず**（23勝24負）反証された

## 1. コーパスでの出現量

`benchmarks/minizinc_challenge/scan_difference_logic.py` で 273 モデルを走査。

| | モデル数 |
|---|---|
| 差分制約を1本でも含む | 197 / 273 |
| hard（無条件）差分制約 10本以上 | 116 / 273 |
| 差分制約が全制約の25%以上 | 56 / 273 |
| 同 50%以上 | 13 / 273 |

全制約 783 万本のうち hard 差分 0.5%、reified/imp 差分 1.4%。
DL が濃い 70 モデルの現況（30秒）は SOL 41 / OPTIMAL 23 / UNKNOWN 6 で、
「解は出るが最適性証明に届かない」帯が主。ここを狙う価値はあると見て着手した。

## 2. Step 1: presolve の STN 最短路 — 効果なし

実装は `feature/difference-logic` の `DifferenceLogicPresolve`
（無条件差分制約をゼロノード付きグラフにし、SPFA で両方向の最短路、負閉路は UNSAT）。

**Phase 1 presolve の後**に走らせて測った（＝ Phase 1 が届かなかったぶんだけが出る）:

| | 結果 |
|---|---|
| DL グラフが構築された | 70 / 70 |
| Phase 1 の後にさらに締まった | **10 / 70** |
| 締めた境界の総数 | **156本**（最大 code-generator の130本） |
| 負閉路（無料の UNSAT）検出 | **0** |
| presolve 時間の差 | ±0.08秒（ノイズ範囲） |

`median-string`(11,970 DL変数) / `table-layout` / `EchoSched` /
`rotating-workforce-scheduling` / `opd` / `cable-tree-wiring` はいずれも **0本**。

**理由**: 制約単位の bounds 伝播を不動点まで回すと、到達する境界は最短路が与えるものと
同じになる。差が出るのは到達の速さ（サイクル上の収束がドメイン幅に比例する）だけで、
presolve は既にその不動点に居る。

## 3. tier 分析: DL 変数の大半は分岐対象でない

| | 割合 |
|---|---|
| decision tier の DL変数 | 29.3% |
| defined tier の DL変数 | **70.7%**（うち presolve で確定済みは 4.3pt のみ） |
| **両端とも decision tier の辺** | **10.5%** |
| 片端だけ decision の辺 | 58.0% |
| 両端とも defined の辺 | 31.5% |

6/70 モデルは DL変数が全て defined tier。`median-string` は 11,970 辺すべてが
「片端だけ decision」で、`X_INTRODUCED = x - y` 型の分解そのもの。

経路は2つ。(a) `ModelSimplifier` が 2変数 `int_lin_eq` で |係数|=1 の片方を**代入消去**し、
消した側を defined にマークする。(b) FZN の `::defines_var` が付いた変数は
`VariableSelector` の defined ゾーンに置かれる（除外ではなく後回し）。

## 4. 昇格アーム — 効果なし、増やすほど悪化

「DL ネットワークのハブになっている defined 変数を decision tier へ上げれば、
ネットワーク上の推論が分岐に届く」という仮説を実装して測った
（`SABORI_DIFFLOGIC_PROMOTE`、70モデル × 3シード × 30秒）。

| arm | セル単位 | 問題単位 | ステータス階層 |
|---|---|---|---|
| promote32 | 25勝23負162分 | 11勝11負 | 改善5/悪化2 |
| promote128 | 20勝30負160分 | 8勝13負 | 改善5/悪化8 |
| promoteAll | 24勝33負153分 | 8勝15負 | 改善6/悪化8 |

「片側しか分岐対象でない」のは**原因ではなく結果**だった。defined 変数は decision 変数から
関数的に決まるので、ネットワークの情報は既に関数依存の連鎖として伝播経路に載っている。
分岐対象を増やしても新しい情報は出ず、decision 層を薄めるぶん悪化する。

## 5. 理論的な決着（これが本丸）

DL が SMT で価値を持つ柱は2つある。この solver ではどちらも成立しない。

**柱1: theory propagation** → §2 のとおり既存の伝播に包含される。

**柱2: theory conflict explanation** → **置き場所が無い**。
SMT の DL solver が本当に効くのは、負閉路を見つけたときに閉路上の辺リテラルの否定を
節として学習し、それが以後の探索全体を刈るから。この solver の NoGood は ground 限定で、
辺リテラル（reified 差分制約の b）を含む節を作る機構が無い。閉路を見つけても
次に活きる形で保存できない。これは LCG の撤退判断（[[lcg-dispatch-direction]]）と同じ壁。

唯一「新しい推論」に見えた reified 辺の論理値決定も、既存機構に吸収される:
- 経路が確定済みの辺だけなら、その情報は境界に載っているので `int_lin_le_reif` が同じ結論を出す
- 未確定の辺が要るなら仮定を置いた推論であり、`SABORI_PROBE_ROOT`（failed-literal 検出）が
  汎用的に既にやっている

DL 専用実装が勝てるのは速度だけで、それは §2 で ±0.08秒（ノイズ）と出ている。

## 6. 派生: 順序グラフ上の位置を分岐方向に使う — 反証

DL の推論ではなくグラフの**形**だけを使う案。`feature/precedence-phase` に独立実装
（`PrecedencePhaseHints`、最短路も STN も使わない）。

**動機となった欠陥は実在する**: `vote_le_pair` は `x <= y` ごとに x へ low 1票・y へ high 1票を
入れるだけなので、連鎖 `x1<=x2<=...<=xn` の内部変数は両方1票ずつで打ち消し合い、
`vote_bisect_dir` がちょうどコイン投げに落ちる。順序構造がいちばん濃い場所で、
票が定義上ゼロ情報になっていた。さらに `build_direction_votes` は defined var の票を捨てる。

**しかし解消しても得は無い**（70モデル × 3シード × 30秒）:

| 比較 | セル単位 | 問題単位 |
|---|---|---|
| prec1（位置由来） vs base | 20勝23負167分 | 9勝9負 |
| prec2（**逆・対照**） vs base | 17勝22負171分 | 10勝12負 |
| prec3（一律 low） vs base | 25勝19負166分 | 10勝11負 |
| **prec1 vs prec2（対照）** | **23勝24負163分** | — |

**位置由来のヒントは、その正反対と区別がつかない。** 情報があるなら逆向きには勝てるはずで、
勝てないということは方向の中身ではなく「決定的に倒すこと自体」しか起きていない。
既に閉じている分岐方向の先験シリーズ（[[bisect-direction-prior-closed]]）の結論と整合する。

対照を置かなければ prec3 の 25勝19負を見て「一律 low がやや良い」と誤読していた
（問題単位では 10勝11負でノイズ）。**この種のアームは必ず反転対照とセットで測ること。**

## 7. 実装上の落とし穴（再実装するなら）

順序グラフの鎖長を**有限回の緩和で打ち切る**と、閉路の中で辺の走査順に依存した差が残り、
順序として等価な変数に恣意的なヒントが付く（= ノイズの注入）。最初の実装がこれで、
閉路のユニットテストで検出した。強連結成分に潰してから縮約 DAG 上でトポロジカル順の
1パスにすれば厳密かつ走査順非依存（O(V+E)）。
