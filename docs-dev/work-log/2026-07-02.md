**設計判断・理由**
- 並列 API は既存 `CpSolver.solve` の引数拡張（別クラスにしない）: 高レベル API を汚さず後方互換最優先。`num_workers=1` + `time_limit` も ParallelSolver(1) 経由にして `proved_optimal` で状態判定を正確に
- タイムアウトは watchdog スレッドが `stop()` を呼ぶ協調停止（C++ に時限 API を足さない）: claude_helper と同じ確立済みパターン
- 非決定性修正は「初出順」: 入力にのみ依存し決定的。アドレス依存の診断では ASLR on/off 比較が無効（ページ整列で下位ビットが保存され `ptr % bucket_count` が変わらない）という落とし穴を確認
- S(k) は実並列 wall-clock で計測（単一スレッド VBS 予測は bound 共有分を過小評価するため）
