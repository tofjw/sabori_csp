## 2026-07-07 01:55 〜 03:00 groupsplitter 調査 → 基盤バグ2件修正で証明付き完勝に反転

**実施内容**
- 棚卸 (c) 探索バケツの groupsplitter（FZN が CP-SAT と byte 一致なのに 60s 解なし）を調査
- **原因1: par 定数配列の全要素が Variable として実体化**
  - parser.yy は `array [1..N] of int:` でも要素ごとに fixed_value の VarDecl を作り、
    to_model() が全てに Variable を生成。groupsplitter はテーブルデータ 483万セル
    → モデルが 4,835,805 変数（presolve verbose で発見・セル数と厳密一致）
  - 修正: 固定値 var_decl の eager 生成をスキップし、名前参照時に
    `FznBuildContext::get_var_by_name` で遅延実体化（出力対象・出力配列要素・
    目的変数は除外）→ 245 変数に
- **原因2: TableConstraint がイベントごとに即時 full filter**
  - 修正1後も 27s/決定で停止。gdb バックトレースで `filter_domains` 内と特定
    （ptrace 不可のため gdb 配下起動 + SIGINT 方式）
  - 全ドメインイベントが O(range×word_scan) の filter_domains を即起動し、
    filter の enqueue が他テーブルの filter を再起動する連鎖で二次爆発
    （arity3×256k行×15本 + arity6×17k行×15本 等の 75 テーブル）
  - 修正: bin_packing_load と同じ batch 集約に変更。イベントは word 更新
    （増分・trail）のみ行い `schedule_constraint_batch`、キュー空時に
    `propagate_batch` → filter 1回。`filter_gen_` を「イベントは現ラウンドに
    マーク / filter_domains が完了時に ++ してラウンドを閉じる」意味論に再構成
    （バッチ集約でも residue 検証の見逃しが出ないように）
- 効果（groupsplitter u15g1pref2, 60s）:
  - 直接 fzn: 解0/fails=0/enumerate=1 → 解6/obj=270/fails=14,140
  - bench 経路: TIMEOUT 解なし → **OPTIMAL obj=279 証明付き・CHECK_OK**（CP-SAT は 135）
- 2025 フル再計測（昨日と同条件）: **Sabori 12 / CP-SAT 3 / Tie 2**（昨日 11/4/2）。
  groupsplitter が勝ちに反転、他は軌道ジッタ範囲（cgt/tsptw/wtv 微改善、新規の負けなし）、
  全勝ち解 CHECK_OK

**設計判断・理由**
- 遅延実体化の例外（出力/目的変数）: 解出力は sol を名前引きするため、出力対象は
  eager 生成が必要。目的変数は find_variable_index で引かれるため同様
- filter_gen_ 再構成が必要な理由: イベントごとに gen を進める旧方式のまま batch 化
  すると、同一バッチ内の先行イベントの word 変更が「未変更」に見え、死んだ residue
  を信じて **under-filtering**（健全だが GAC 喪失）になる
- 両修正とも軌道可変（定数遅延化は par 配列を持つ全問題の変数 id 空間を変える）。
  golden 差分 5 件は解集合同一（機械照合）を確認して再記録

## 2026-07-07 06:30 〜 07:40 subcircuit の footprint 定量化 → native 化

**実施内容**

  分岐対象の増加。**CP-SAT は fzn_subcircuit を native 保持**（ギャップ実在）

- `SubcircuitConstraint`: ステートレス全再計算 batch。alldifferent は registry が
  併設（circuit と同流儀、閉路構造の推論に専念）

  - R2: 閉路確定時、外側の全ノードを自己ループに強制（2つ目の閉路は矛盾）
  - R3: 確定非自己エッジの先 j は in-circuit → self を除去
  - 歩行は visited 防御付き（alldiff 伝播前の入次数≥2 でも停止保証。
    既存パスへの合流は閉路と区別して無視）
