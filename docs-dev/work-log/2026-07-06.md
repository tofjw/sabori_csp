## 2026-07-06 22:20 〜 23:10 global_cardinality native 実装

**実施内容**
- 棚卸の提案 #1 `fzn_global_cardinality` を native 実装（feature/more_constraint）
  - `GlobalCardinalityConstraint`: bin_packing_load と同型のステートレス全再計算
    batch propagator。open 意味論、重複 cover・cover 外値・gap ドメイン対応
  - 伝播: counts bounds [definite, definite+possible] / distinct cover 限定の
    sum reasoning（Σcounts vs cover 値を取り得る・取らざるを得ない変数数）/
    include・exclude 逆伝播
  - mznlib: `fzn_global_cardinality.mzn` + `fzn_global_cardinality_low_up.mzn`
  - registry / Python bindings / docs/CONSTRAINTS.md / テスト一式
- テスト: ctest 272/272、golden 249本 ALL GREEN（既存 expected 変更ゼロ）。
  C++ brute-force 同値テスト6ケース、fzn 4本を golden 登録
- 効果（60s 単一シード）: mondoku FZN 2421→2037制約（native×48 = CP-SAT と同数）、
  fzn 直接実行で解0→1。tower obj=58 不変、work-task-variation obj=3625→3202 改善

**設計判断・理由**
- open 意味論で実装（std の fzn_global_cardinality と一致。closed は std が
  membership を足すので native 側は open だけで良い）
- sum reasoning は cover が distinct のときだけ（重複 cover では Σcounts が
  同一値を二重に数えるため不健全）
- mznlib の low_up 再定義は独立ファイルが必須: MiniZinc の include 解決は
  ファイル名単位なので、fzn_global_cardinality.mzn 内に low_up を書くと
  std/fzn_global_cardinality_low_up.mzn と二重定義エラーになる
