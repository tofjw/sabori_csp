### 設計判断・理由

- **統合順を「主力 → fix」にした**。主力 31 コミットのほうが main 側 11 コミット（docs とビルドのみ）と
  ぶつかる可能性が高く、先に解決しておけば fix 3 本は素通りするため。実際そうなった。
- **CMakeLists の衝突は main 側（HEAD）を全採用**。ブランチ側 `9c45cea` の mznlib clean copy は
  main 側 `6eb14ac` と実質同じ変更で、解決後のファイルは統合前 main と**バイト単位で一致**した。
  衝突していたのは main だけが持つ install ターゲット（`d40da44`）のブロックで、
  ブランチ側は「そこに何も無い」状態だったため、両者の実体は競合していない。
- **削除は `-d`（安全削除）のみ使い、`-D` は使わない**。`worktree-agent-*` は main マージ済み
  （`git branch --merged main` に出る）なので `-d` で落ちる。落ちないものは統合漏れなので消さない、
  という線引きにした。
- **worktree の未コミット変更は捨てる前に patch 化した**。`git worktree remove` が `--force` を
  要求した＝作業中の変更があるということなので、`tmp/worktree-backup/agent-*.patch` に退避。
  内容は main より 247 コミット遅れの IntLinLe early-break / cumulative 実験で、
  復元価値は低いと判断したが、判断の取り消しは user に委ねる。
- **統合前の状態にタグを打った**（`backup/pre-integration-main` / `backup/pre-integration-scc`）。
  マージコミット 4 つ + ブランチ削除 6 本をまとめて戻す必要が出たときのため。
- **push はしない**。指示が無く、40 コミットの公開は独立した判断なので。
