**提案**: 証明ネック問題で bool 系の制約伝播呼び出しが過剰では?

- 無駄打ち率: **array_bool_and は呼び出しの 52.3% が充足済み制約**への着弾。
  bool_clause は 1.8% のみ（2WL watch が既に有効）→ 対象は array_bool_and

**実装**
- Model に constraint_entailed_ (uint8 フラット配列) + entailed_trail_。
  set_constraint_entailed(c, sp) / is_constraint_entailed(c) inline。
  rewind_dirty_constraints で sp より深いフラグを解除（バックトラック復帰）
- dispatch 6ループ + batch pop に `if (entailed) continue;` を仮想呼び出し前に挿入
- ArrayBoolAnd の 5 箇所で entailment 検出（r=1全強制 / r=0&∃b=0 / r=0残り1強制 /
  b=0→r=0 / 全b=1→r=1）

**重要な発見: 純粋 no-op ではなく軌道可変だった**
- 当初「スキップ＝厳密 no-op → 軌道不変」と想定したが hrc で解ストリーム分岐を検出
- 機構: entailed 後の callback は整合状態では no-op だが、**同一伝播波内の過渡的
  矛盾状態では「矛盾の検出者」として fail → bump_activity していた**。スキップに
  より矛盾検出がキュー層に移り bump が消える → activity → 変数選択が変わる
- 健全性は不変（矛盾は必ずキュー層で検出される）。二分実証: dispatch スキップのみ
  （フラグ設定なし）では完全一致 → 分岐はフラグ発動時のみ

## 2026-07-08 09:30 〜 11:00 IntEqImp への entailment 展開 → 計測の結果 不採用

**動機（ユーザ指摘）**: imp は reif より軽いはずなのに A/B で net±0 = 工夫不足では。
最大の理論的優位「b=0 なら永久に無関係」が実行時コストに反映されていない。

**実装（→破棄済み）**: IntEqImp の全コールバックに entailment 検出 8 箇所
（b=0 vacuous / b=1+等値固定 / x,y確定 / 対偶 b:=0 強制後）。ctest 299/299 green。

**計測（bench_int_eq_imp.py、同一バイナリベースで patch 有無の対照実験）**
- Round 3 (patch あり): net(imp) = −12 (31/43/96)
- Round 3b (patch なし): net(imp) = −1 (37/38/95)
- 分離分析: ノイズ床 (base vs base、意味論同一) = net −3/15 決着セル
  → **30s wall-clock + 並列負荷のタイミング非決定性**が存在し、ab3 実行時の方が
  高負荷だった系統バイアスを検出（base 列は本来完全一致のはず）
- パッチ純効果 (imp vs imp) = net −12/56 決着セル。**セルあたりの負け率は
  ノイズ床と同率 (−0.21 vs −0.20)**、有意水準 ~1.6σ → 「害がある」とまでは
  言えないが「利得なし」は確定

**なぜ ArrayBoolAnd では効いて IntEqImp では効かないか**
1. imp アームの定数側 imp の大半は aggregator が IntOneHotChannel に吸収済みで、
   IntEqImpConstraint として残る個体数が少ない（hitori: 1295/1484 が channel 行き）
2. ArrayBoolAnd は「無駄打ち 52% × 3,366万回/20s」という物量があった。IntEqImp の
   残存個体にはその物量がない
3. b=1 強制系の entailment は伝播キューの順序を変える（軌道 re-roll）だけで
   コスト削減が小さい
4. **imp vs reif が wash な本質は「コスト」ではなく「推論力のトレード」**:
   reif は b=1 を推論して他制約に供給できる（imp は不可）。imp のコスト減 ≒
   reif の推論益、が3ラウンド通しての一貫した説明

**教訓**
- 30s wall-clock ベンチには並列負荷の系統バイアスが乗り得る。A/B の解釈では
  「意味論同一の列」をコントロールに入れて床を測るのが有効だった
- entailment フラグの展開判断は「無駄打ち率 × 物量」の事前計測（gprof + 一時計装）
  を先にやる。ArrayBoolAnd 型の物量がないなら期待値は薄い
