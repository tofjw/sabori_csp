**設計判断・理由**
- 各段で「推測せず先に実測」を徹底（step 0 で自動ベクトル化ゼロ仮定を棄却、step 1 で table 寸法実測→広テーブルは sparse ルーティングで dense に来ないと判明、step 2 で celar/nside の arity・係数を実測）。
- SIMD/SoA/idiv 除去が全て中立だった根因＝**このソルバは compute 律速でなく memory-latency / algorithm 律速**。散在変数アクセスのキャッシュミス遅延・伝播カスケードが支配し、算術スループット改善が効かない。
- cumulative だけ効いたのは TTEF が本当に compute/algorithm 律速だから（O(P) プロファイル走査は実在の仕事）。→「vectorization より algorithm/locality が先」というテーゼが数字で確定。
- 中立コミット（step 0/2）も残した理由：step 0 は安全な既定＋手書きカーネルの前提、step 2 は除算フリーで無害。コミットメッセージに「neutral・なぜ残すか」を明記し再探索を防ぐ。
