## 2026-07-05 10:44 int_lin_eq 動的スラック上界（静的スキップの拡張）

**実施内容**
- 静的上界（根の max|c|*width）は domain が縮むと緩く、slack が大きい時しか発火しない。**動的上界 max_contribution_** を実装: フルスキャン（非skip 呼び出し）時に**厳密な max_j|c_j|*width_j へ締め直し**、`rewind_to` で静的上界へリセット。→ commit 354e41c

## 2026-07-05 11:38 no-op スキップの int_lin_le / int_lin_le_imp 横展開

**実施内容**
- int_lin_eq の動的スラックスキップを不等式制約へ横展開。`Σc_j x_j ≤ bound` で prune 可能 ⟺ `|c_j|*width_j > S`（S = bound − total_min）。同型の動的上界（フルスキャン時に厳密 max へ締め直し／rewind_to で静的リセット／トレイル不要）で `S ≥ max_contribution_` を skip。→ commit e546286
- **int_lin_le**: 既存の O(n) エンテイルメントループ（total_max ≤ bound 判定）を、その**上位集合の O(1) スキップ + リフレッシュ**に置換（no-op 呼び出しが O(n)→O(1)、エンテイルメント ⟹ 私のスキップ発火なので coverage 減らない）。
- **int_lin_le_imp**: エンテイルメント無し。b=1 の伝播経路に同型スキップを追加。
- 効果: **opd +46%**（int_lin_le/le_imp が律速）。ihtc/code-generator 中立（le/le_imp が hot でない）。

**設計判断・理由**
- 健全性: `prune_sum_le` は純粋関数（実際に締まる時だけ enqueue、no-op で無副作用）＋ skip 条件が prune 条件と数学的に厳密一致 → **domain 枝刈りは不変で sound**。opd/mrcpsp/rcpsp-wet すべて同一最適値、266 green + 線形 brute(4714)。
- **軌道差の機構を特定**: mrcpsp は両版とも obj=27 を 0.07s で最適証明するが fails が決定的に異なる（316 vs 277, nogoods 65 vs 66）。原因は「no-op を速く返す → 制約間の伝播順序が変わる → 複数制約が導ける境界の nogood 理由帰属が変わる → 学習節が変わる」。**LCG 系で既知の健全な現象**（正しさ不変、最適一致）。int_lin_eq が celar で完全同一だったのは順序影響が節帰属を flip しなかった偶然。
- 判断: 健全＋opd 実益大なので採用。ただし「no-op スキップは挙動中立ではなく軌道を動かしうる（sound）」と明記。
