**設計判断・理由**
- **中心的知見: 伝播等価以上・モデル小でも、分解の補助 bool を消すと負けうる**。
  `__sir_b1/b2` は defined 層で分岐こそされないが、bump の blame 受け皿・解 NG の
  リテラル（golden 差分で解 NG 3→1 リテナルに短縮が観測できた）・decision 枯渇後の
  分岐材料として探索エコシステムに参加していた。「構造的に綺麗 ≠ 速い」の再確認
- 階層（decision/defined）の扱いは意図的に不変: b のマーキングは native/decomp 分岐の
  前にあり比較から階層効果を排除。失われたエコシステムを階層操作で補償する実験は
  9/22 の6ゲート閉鎖を踏まえ実施しない。native は decomp と正反対の軌道を作るので
  mp arm 分化の種として温存
- **集約系機能が複数あるときの採否判定は 2×2 要因計画が必須**: 最初の単独 A/B は
  decomp 腕の __sir ペアを順序チャネルが拾い「native vs decomp+OC」に交絡していた
- 運用ミス2件（再発防止をメモリに記録）: ベンチ実行中にビルドして A/B を汚染（再走で
  回収）/ 停止時の pgrep -f が自シェルに自己マッチ（[b]ench 形式で回避）
