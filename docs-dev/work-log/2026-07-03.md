**設計判断・理由**
- 「シード優先・軸は疎に」: データは純シード優位だが、軸は特定インスタンスでの大勝ヘッジ（未計測の問題クラス対策）として疎に残す。16問/12s への過学習を回避
- worker0 = base 固定は維持（単一スレッドより悪くならない保証）
- 新旧比較は統一レンジ再正規化: score の best/worst 正規化は run 内クローズドで、別 run の直接比較は不正
- 採用基準を「k=1 新旧一致 + 全 k で ≥ 旧 + 低 k の傾き改善」と定義し、実並列 S(k) を最終審判とした（単一スレッド VBS は bound 共有の超加法性で下界にすぎない）
