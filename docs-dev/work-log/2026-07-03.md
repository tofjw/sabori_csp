**設計判断・理由**

- 問いを「どのポリシーが速いか」ではなく「フィードバック信号は情報を持っているか」に設定
  （scrambled 対照 = レート合わせコイントスで信号との結合だけを切る）。fixed 側はチューニングせず
  文献標準値を並べ、oracle/worst framing で「保険」仮説を検証（mix_p §1 と同じ型）
- objective 比較の前にマニピュレーションチェック（Bloom 93% no-op の教訓）→ これが退行発見に直結した
- 退行は「修正」せず、env 設定時のみライブ信号（`restart_signal_live_`）を読む設計。
  未設定は出荷挙動を保存（golden を守る）。出荷挙動と等価な `always_widen` アームをブリッジにして
  「蘇生の価値」自体をベンチで判定 → 同着（net+7）なので既定を変える理由なし
- scrambled の p=0.065 は instrumentation の経験的 tighten 率（8問×2シード）
