### 設計判断・理由

- **「両方採用」の機械適用は危険**と分かった。`=======` を行頭アンカーなしで検出したため
  `// ======` のバナーコメントに誤マッチし、`graph.hpp` と `test_graph_constraints.cpp` で
  **SubcircuitConstraint のクラス本体・テスト本体が途中で切れて消えた**。
  コンパイルエラーで露見したが、コメントやデータファイルだったら黙って通っていた。
  最終的に「main 版を土台に、ブランチ側のブロックだけを行範囲で切り出して挿入」する形に変えた
- **事故の復旧は履歴の作り直しを選んだ**。`git rm --cached` で外すと巨大ファイルが
  オブジェクトに残り続ける（`.fzn_cache_*` だけで61MB超）。`origin/main` は `c814ed0` までで、
  汚れた分は push されていなかったので作り直しが安全に選べた
- **作業ツリーの復旧を先にやった**。ブランチ切替時に git が巻き込みファイルを
  「追跡ファイル」として削除していた（`memo.md` / `findy/` / `a.mzn` / `.fzn_cache_*` 等）。
  コミット済みだったのでオブジェクトから復元し、`git reset HEAD --` で未追跡に戻した。
  セッション開始時の未追跡34件と一致することを確認してから履歴操作に進んだ
- **main を動かすのに `git checkout` を使わなかった**。未追跡ファイルが存在する状態で
  main（汚れた側）に切り替えると git が拒否する/また消す。`commit-tree` で親2つの
  マージコミットを直接作り、`git branch -f` と `git symbolic-ref` で付け替えることで、
  作業ツリーに一切触れずに main を差し替えた
- **.gitignore はスクラッチのスクリプトを無視しない**方針にした。無視すると
  `git status` から消え、コミットし忘れた作業が黙って失われる（2026-07-22 の実例。
  reflog からも復元できなかった）。ノイズとして見え続ける方が安全側
