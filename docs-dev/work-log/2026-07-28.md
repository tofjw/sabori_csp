**設計判断・理由**

- **build ツリー用と install 用の .msc を 2 本立てにした**。CMake の build-tree export /
  install-tree export と同じ形。install を開発ループに挟むとブランチ切替のたびに prefix 側が
  古くなり、ベンチの信頼性が落ちる。build ツリー用 .msc の生成内容は 1 バイトも変えていない
- **install 先の .msc は絶対パスを焼かず相対パスで書く**。configure 時の `CMAKE_INSTALL_PREFIX` を
  埋めると、後から `cmake --install --prefix ...` で上書きされたときに嘘になる。
  相対関係は prefix に依存しないので configure 時に `file(RELATIVE_PATH)` で計算すれば足りる
  （絶対 BINDIR/DATADIR を指定された場合だけ絶対パスにフォールバック）
- **JSON の定義元を `sabori_csp.msc.in` に一本化**。`$<TARGET_FILE:>` が要る build 側は
  「configure_file でジェネレータ式を文字列のまま埋める → `file(GENERATE INPUT)` で展開」の
  2 段構えにした。これで定義の二重化がなくなり、孤児テンプレートも復活
- **mznlib は build のコピーではなくソースの正本から install する**
- **ブランチは main + `9c45cea` cherry-pick**。install ブロックが `SABORI_CSP_MZNLIB_SRC_DIR` に
  依存しており、この変数は `feature/subcircuit-scc` 側の mznlib clean copy コミットが導入したもの。
  cherry-pick して subcircuit の作業とは独立に main へ出せる形にした
