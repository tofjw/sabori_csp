## 2026-07-09 H-A 実装: bottom-up optimistic probe (SABORI_BOTTOMUP, opt-in arm)

**実装** (`run_bottomup_probe`, improvement probe の対称形)
- リスタート時に obj <= lb+δ を投機: SAT → 準最適へジャンプ / 証明付き UNSAT →
  root で lb 引き上げ (健全) / UNKNOWN → δ 半減 + 長期撤退 (skip 64<<streak)
- **staircase ポリシー**: UNSAT が続く限り 1 呼び出し内で連続して階段を登る
  (生産的な間だけ投機を続け、決着しない問題では本探索に道を譲る)
- 学習 NoGood は仮定 (Leq/Geq) を decision literal に含む条件付き連言 = 大域健全

**実装中に踏んだバグ 2 件（教訓）**
1. run_search の cl は「フレーム毎リトライ予算」で深さ方向に爆発する
   (500 指定で 217k fails)。グローバル予算は restart_fail_cutoff_ を使う
2. probe 後に var_selector_.init_tracking + unassigned_trail_.clear() が必須
   (improvement probe の呼び出し元と同じ処置)。怠ると本探索が解を見つけられなく
   なる (gfd で解ゼロとして発現)

**ポリシー試行錯誤**: 固定500=中立 → 適応倍増=全面悪化 (投機が本探索を食う) →
staircase + 長期撤退=採用

**結果 (30s, off vs SABORI_BOTTOMUP=20000)**
| 問題 | off | on20k |
|---|---|---|
| zephyrus15 (opt=12) | 5834 | **12 = 最適値** (bench経路 CHECK_OK, gecode/CP-SAT とも一致) |
| gfd-schedule22 (opt=9) | 642 | **142** |
| roster-shifts-bool23 (MAX) | 27975 | **28890** |
| arithmetic-target22 | 108 | 3106 (悪化) |

問題依存の諸刃 → **opt-in arm として温存** (LNS/-C と同じ棚)。既定オフのため
ctest 299/299・golden 260 不変。budget は 500 だと中立、20000 で大勝ち/負け
が分かれる = ポートフォリオ arm としてワーカー 1 本に載せる価値あり

## 2026-07-09 追記: 相転移カットオフ（ユーザ提案）

**仮説**: SAT/UNSAT 境界に接近すると UNSAT 証明が指数的に重くなる（相転移）
→ コスト急増を検知したら階段を切るべき

**実測（step_fails 計装、zephyrus opt=12）**: target=5: **0** → 7: 2,519 →
9: 4,751 → 11: **>20,000（壁）**。超線形上昇 = 相転移プロファイルが数値で確認。
gfd は初段（lb=4, opt=9）から壁 = 改善の源泉は activity 転移のみと判明

**実装**: 証明成功でも step_fails > 予算/8 なら「境界接近」と判定して階段を
停止（lb 進捗は保持）、UNKNOWN と同じ長期撤退。壁ステップの予算丸損を予防

**結果（30s, budget=20000, cutoff なし → あり）**: zephyrus 12→12 維持
（target=7 で切り上げても lb 伝播で本探索が完走）、gfd 142→142、
roster 28890→28890、**arithmetic 3106→887（負け幅 1/3.5）**。全問題で改善か同等

## 2026-07-09 G3 攻略可能性調査

**実施内容**
- G3 (数値 bound 証明型) 5問に bottomup probe を適用して攻略可能性を調査
  - まず既定 arm (b2k/b20k, 30s): 全問 SOL のまま証明ゼロ、obj も実質不変
  - -v で階段を観察 → rcpsp は lb 45→60 が step_fails=0（TTEF+precedence 即答）、
    68 まで無料同然と判明 → 「prover 構成」(budget 10M / cutoff 無効) を試行
- prover 構成の結果:
  - **rcpsp13: OPTIMAL 完全証明 118s 単スレ**（CP-SAT 12s の約10倍だが閉じる。
    probe が incumbent 発見 82→79→77 と lb 証明の両輪を担った）
  - mapping15 / depot16: probe jackpot で最適値 (793 / 13995) は即発見するが、
    lb が 511/793・8191/13995 の壁で 300s でも不動
  - largescheduling: lb が incumbent の 63% まで全段無料登坂、b20k で obj 微改善
  - liner-sf: 毎段 ~20k fails × obj スケール 4M で階段が構造的に遅い（arm 微負）

**設計判断・理由**
- **G3 を G3a/G3b に分割**（loss-taxonomy-20260709.md に記録）
  - G3a (schedule-bound 型) = 攻略可能。obj≤K が cumulative/precedence に直結し
    lb 階段の大部分が無料。G1 は jackpot (SAT側) が武器、G3a は UNSAT 側階段が本体
  - G3b (int_max 集約型) = 射程外。obj=max(e_i) の「obj>K」は全 e_i≤K の一括
    フィージビリティ反証で漸進化できない → 節学習の領分、外部ポートフォリオ枠
- prover 構成は単スレ 30s では解探索を飢えさせる（rcpsp UNKNOWN 化）ので
  既定にはしない。feature/mp で budget 違いワーカー（b2k + prover 10M）を
  並べるのが正しい形
