  - 原因: `ParallelSolver::build_workers()` が `stop_flag_` を false に戻すため、
    `prep.prepare()`（presolve）中に alarm → `stop()` が届くと停止要求が消える

    clone を作らず UNKNOWN で戻る。Python に `ParallelSolver.reset_stop` を公開
  - 修正後 `-t 1` は 10.7 秒（残りはパース + presolve）。回帰テストは修正前の挙動で失敗することを確認
- 結果: 通常ビルド ctest 330/330・golden 272/272・pytest 132。TSan ビルド ctest 330/330
  （スイープ 816 回、レポート 0）。ベンチの大きい問題 8 本（ma-path-finding 含む）も `-j4` でレポート 0

**設計判断・理由**
- スイープの判定は競合と異常終了だけにした。解の正しさは `[clone]` / `[resolve]` / golden が担う
- golden コーパスは小問題ばかりで、816 回が約 8 秒で終わる。長く走る経路（bound 共有・

  作り直しており、C++ にも使い回している箇所はないので互換性の問題はない
