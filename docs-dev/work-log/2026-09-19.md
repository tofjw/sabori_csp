### 設計判断・理由

- **3段ゲートの順序にした**（余地 → 勝者の安定性 → 特徴の判別力）。案2 の素朴な実装は
  「特徴を作って分類器を回す」だが、その手前に**特徴量の質と無関係に決まる関門が2つ**ある。
  実際 Gate2 で折れたので、分類器を書かずに済んだ
- **プローブで証明が終わる 24 問を除外した**。ここを混ぜると「どのアームでも同じ」が
  母数を膨らませ、判別力の議論が薄まる。ただし除外した結果、残り 53 問は難しめに偏るので、
  **この母集団を既定フラグ昇格の根拠には使えない**（メモに明記した）
- **並べ替え検定を入れた**。特徴量が約 20 個あるので、生 AUC の最大値は多重比較で
  簡単に 0.8 に届く。ラベルをシャッフルした帰無分布（中央値 0.20〜0.28）と比べて初めて
  「ノイズと区別できない」と言える。[[never-conclude-from-single-run]] の系統の対策
- **総当たり勝ち点と直接対決を両方出した**。勝ち点順位だけ見ると probe_root が base の上に
  来るが、これは弱いアーム（clause_witness / promote_impact）から点を稼いだ結果で、
  一騎打ちでは互角。**後からこの表だけ読んで既定を差し替える誤読を防ぐため**、
  注記付きで両方残した
- **マージでなく移植を選んだ**（mp 系）。merge-base は 2026-06-29 で main はそれ以降
  247 ファイル・19,527 行動いているが、内訳を測ると差は小さい——新規4ファイル(1,263行)は
  衝突ゼロ、各制約の `clone()` はどちらでも必須。`Constraint::clone()` は純粋仮想で、
  main に増えた 7 クラスが未実装なので**マージしてもビルドは通らない**。
  実質の差は約 800 行のフックハンクで、そこは 2026-09-17 に auto-merge が壊れた帯域と同じ
