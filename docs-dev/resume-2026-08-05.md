## 6. 計測上の注意（このセッションで 5 回間違えた）

**単一実行の差から系統差を結論してはいけない。** 最低 5 シードで分布を見る。

- 60 秒でタイムアウトする行は非再現（同一設定の再実行で OPT ⇄ TIMEOUT に振れる）
- 終了するモデルの fails は決定的。強度を見たいならそちらを使う
- ただし **fails の差は枝刈り強度の指標にならない**（インクリメンタル伝播は内部状態を持ち、
  イベント順序で軌道が分岐する）。強度を見たいなら「不動点での全スキャン差分」
- minizinc 経由で測るときは flatten フラグがモデルを変えていないか（変数数）を確認する
  （`--output-mode dzn` が自由変数を 60 本増やしていた事例あり）
- 壁時計時間は並列実行数でぶれる。`/usr/bin/time -f "%U"` の CPU 時間を使う

詳細はメモリ `never-conclude-from-single-run` に集約済み。
